5. Remediation Proof – Main innovative feature
Core innovation
Remediation Proof
A time-limited, inspectable evidence certificate created before any recovery action.
It records:
What went wrong.
Why the system suspects a particular service.
What evidence supports the diagnosis.
What recovery action is proposed.
Which services and resources can be affected.
Whether the action is permitted.
How the system will verify the recovery.
How the system will reverse the action if it fails.
Automatic Proof Generation – Generate a proof before executing remediation.
Evidence References – Attach supporting logs, metrics and traces.
Root Cause Evidence – Include ranked root-cause candidates.
Graph Version Recording – Record the dependency graph version used for diagnosis.
Counter-Evidence Recording – Include evidence against the diagnosis.
Blast Radius Documentation – Specify the maximum permitted impact.
Action Documentation – Record the exact proposed recovery action.
Inverse Action Documentation – Record how to reverse the action.
Policy Decision Recording – Include why an action was allowed or denied.
Guardrail Documentation – Record the safety limits.
Canary Measurement Recording – Store control and treatment measurements.
Proof Expiration – Automatically expire outdated proofs.
SHA-256 Integrity Hash – Generate a hash to detect changes to proof contents.
Proof Revalidation – Recheck evidence and permissions immediately before execution.
Proof Export – Allow users to inspect and export remediation proofs.

Target Validation – Reject ambiguous or unauthorized targets.
Blast Radius Limits – Restrict how much infrastructure can be affected.

This is one of the most important parts of the project.

90% Control Group – Keep the remaining traffic on the original configuration.
Treatment vs Control Comparison – Compare the changed environment against the unchanged environment.
Canary Health Monitoring – Monitor service performance during testing.
Incremental Promotion – Progressively increase traffic from 10% to 25%, 50% and 100%.
Automatic Promotion – Promote only after successful guardrail checks.
Regression Detection – Detect when a proposed recovery makes performance worse.
Automatic Rollback – Reverse a failed remediation.
Rollback Verification – Verify that the original configuration was restored.
Rollback Failure Escalation – Escalate if rollback cannot be verified.
Missing Telemetry Protection – Stop promotion if telemetry becomes unavailable.
Canary Failure Explanation – Show exactly why a recovery was rejected.
Recovery State Tracking – Track every stage of the recovery process.
